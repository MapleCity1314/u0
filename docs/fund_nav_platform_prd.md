# 用户在线估值平台 PRD（草案）

日期：2026-02-02

## 1. 背景与目标
用户希望在网页端快速查询基金的盘中估值，并可将基金加入自选列表，在个人 Dashboard 中查看实时估值变化。系统采用：
- 后端：FastAPI
- 前端：Next.js

目标：
- 提供稳定、低延迟的估值展示
- 支持搜索/添加自选基金
- 提供个人化 Dashboard

非目标：
- 不做交易、下单、开户等功能
- 不提供投资建议，仅展示估值/行情信息

## 2. 用户画像与使用场景
- 个人投资者：关注基金盘中走势，频繁查看估值
- 轻度用户：偶尔查询基金走势或验证盘中涨跌

主要场景：
1) 搜索基金 -> 查看估值
2) 添加基金到自选 -> Dashboard 查看实时估值
3) 删除/调整自选顺序

## 3. 核心功能需求
### 3.1 搜索与基金详情
- 支持按基金代码/名称搜索
- 搜索结果展示：基金名称、代码、最新净值、估算涨跌幅
- 基金详情页展示：
  - 最新净值
  - 估算涨跌幅（实时）
  - 估算来源/覆盖率（可选）

### 3.2 自选列表与 Dashboard
- 用户可添加/移除基金到自选
- Dashboard 显示自选基金列表
  - 名称/代码
  - 实时估算涨跌幅
  - 更新时间
- 刷新机制：可配置轮询（默认 60s）

### 3.3 用户与会话（邀请码）
- MVP 阶段采用“邀请码登录/注册”机制
- 已有用户可生成邀请码，邀请新用户加入
- 新用户必须提供有效邀请码才能注册
- 登录后数据与用户绑定（自选、偏好）

### 3.4 后端估值与数据源
- 估值引擎使用 AkShare 数据源
- 支持多层兜底（估值 > 持仓 > 行业 > 指数）
- 需要记录估值来源与覆盖率

## 4. 需求优先级（MVP）
P0：
- 基金搜索
- 自选基金列表
- 估值实时展示
- 基本缓存与限流
- 邀请码登录/注册

P1：
- 登录与多端同步自选
- 估值历史曲线
- 估值来源提示

P2：
- 订阅提醒（涨跌幅阈值）
- 自选分组/排序

## 5. 系统架构（初版）
- 前端（Next.js）
  - 搜索页面
  - Dashboard 页面
- 后端（FastAPI）
  - 搜索 API
  - 估值 API
  - 自选管理 API
- 数据层（初期）
  - 内存缓存 / 简单持久化（sqlite）
  - 后续扩展到 Redis

## 6. API 设计草案
- GET `/api/funds/search?q=`
  - 返回基金列表
- GET `/api/funds/{code}`
  - 返回基金详情 + 实时估值
- POST `/api/auth/register`
  - 入参：邀请码、用户名/密码（或邮箱）
- POST `/api/auth/login`
  - 返回访问令牌
- POST `/api/invites`
  - 已登录用户创建邀请码
- GET `/api/invites`
  - 查看自己创建的邀请码状态
- POST `/api/watchlist`
  - 添加基金
- DELETE `/api/watchlist/{code}`
  - 删除基金
- GET `/api/watchlist`
  - 返回自选列表

## 7. 关键指标（KPI）
- 搜索响应时间 < 300ms（缓存命中）
- Dashboard 刷新 < 2s
- 估值稳定性：实时数据失败时不中断

## 8. 风险与约束
- AkShare 数据源稳定性波动
- 实时行情受限于第三方接口
- 估值误差不可避免，需要免责声明
- 邀请码系统需要防滥用（频控、失效机制）

## 9. 里程碑（建议）
- M1：API 核心接口 + 基础前端页面
- M2：自选体系 + Dashboard
- M3：稳定性增强（缓存、降级、重试）
